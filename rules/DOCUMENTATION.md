# Documentation

本文件是项目文档职责和更新时机的单一事实来源。

## 职责

- `AGENTS.md`：短小稳定的项目导航器；只说明启动顺序、上下文、关键门禁和中央规则路由。
- `PROJECT_BRIEF.md`：用户确认后的需求单一事实来源；不保存开发进度。
- `PROJECT_STATUS.md`：仅保存当前阶段、任务、完成项、进行中、待办、阻塞、最近验证和下一步；删除过时状态。
- `DESIGN.md`：架构、组件、数据流、模型、接口、关键决策、约束和风险；不复制 brief 或进度。
- `README.md`：面向用户和开发者说明项目、功能、运行、构建、测试和结构；不放 AI 工作规则或 Debug 历史。
- `CHANGELOG.md`：记录值得用户或开发者知道的版本变化；不复制提交列表或每个微小操作。
- `CODEX.md`：仅保存项目特有环境、工具、约束或发布方式；没有特殊规则时不创建。

历史由 Git 和 `CHANGELOG.md` 承担；`PROJECT_STATUS.md` 不是日志、日记、思考记录或聊天摘要。

## 更新时机

普通 Task Batch 只更新真正受影响的文档。大阶段完成时检查 brief、status、design、README 和 changelog，有实质变化才更新。

需求边界变化先经用户确认再更新 brief；架构或数据模型实质变化更新 design；用户可见行为变化更新 README / changelog；任务状态变化用最短文字替换 status 中的旧状态。

文档应与代码同一任务同步，禁止明知已过时仍宣布完成。不要为了形式创建空目录、无意义文档或重复规则。
