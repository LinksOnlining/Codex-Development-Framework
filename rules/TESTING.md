# Testing

本文件是验证强度、测试选择、回归与 PASS 门禁的单一事实来源。

## 风险分级

### L1

低风险、可逆、局部修改：执行快速检查或最小可运行验证。

### L2

普通功能或中等影响修改：执行当前功能的针对性测试和受影响路径的必要回归。

### L3

安全、权限、金钱、数据完整性、Schema / Migration、核心算法、重大架构或大规模重构：执行完整验证、必要回归和工程审查。

## 选择检查

按项目技术栈和改动风险选择类型检查、lint、单元测试、集成测试、API / 数据库测试、构建、实际运行、异常路径、回归和用户视角测试。不存在或无法执行的检查标记为 N/A / 未执行，并说明原因和影响。

测试应验证可观察行为与风险，不机械镜像实现。小改动不必每次跑全套；大阶段和最终交付运行完整相关套件。新增复杂逻辑或修复缺陷时，保留一个能防止回归的最小有效检查。

## PASS 门禁

代码或配置修改后必须真实执行适合的验证，未运行不得声称 PASS。

关键验证 FAIL 时：

1. 停止进入下一关键阶段；
2. 诊断根因；
3. 最小范围修复；
4. 重新执行失败检查及必要回归；
5. 直到 PASS，或确认存在需要用户决定的真实阻塞。

不要无休止重复同一失败动作；证据不变时改变排查策略并按 `rules/DEBUGGING.md` 扩大范围。

## 阶段与交付

大阶段完成必须覆盖主要成功路径、关键异常路径和受影响回归。最终交付还应按项目需要验证安装、启动、构建、数据保留、安全、性能、UI / UX、文档与用户首次使用体验。
