# ADR 0004: 配置校验拒绝未知字段

- 日期：2026-08-23
- 状态：已采纳

## 背景

配置字段拼写错误如果被忽略，程序会静默使用默认值。使用者看到配置文件表面上被接受，却得到与预期不同的行为，问题通常要到运行时才暴露。

## 决定

`validateAppConfig` 采用严格模式：输入对象中出现类型定义之外的任何字段即校验失败，并把未知字段与其他字段错误一起返回。

## 原因

- 立即暴露拼写错误，而不是静默回退默认值。
- 保持配置契约明确，样例文件和类型定义可以互相验证。
- 当前项目没有需要兼容多版本配置的外部用户，严格模式的兼容性代价可控。

## 影响与重新评估条件

配置文件不能携带未来版本新增字段并继续被旧版本接受。若项目出现多版本配置兼容需求或外部用户需要滚动升级，应新增 ADR 重新评估版本化配置、迁移策略或受控宽松模式，不直接放宽当前校验。
